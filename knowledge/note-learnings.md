# note執筆の学び（公開後に育てる）

> 記事を公開するたび、`write-article` スキルの「公開後フロー」で追記していく。
> 執筆前にここを読むことで、過去の学びが次の記事に効く（複利）。
>
> 役割分担：このファイル＝「なぜ効いたか」の教訓（言葉）。反響記事の実物（お手本）は `samples/`（[samples/README.md](samples/README.md)）。

## 効いた切り口
（例）2026-06-xx「記事名」：◯◯という入り方は反応が良かった。

- **本文の具体的な体験に、関連する過去記事リンクを差し込む**と、回遊と文脈の厚みが出る。
  単に末尾に並べるのではなく、本文でその話題に触れた箇所（例：「小1の壁」「昇給」）に自然に結びつけるのが効く。
  初出は [samples/2026-06-25-minimum-wage.md](samples/2026-06-25-minimum-wage.md)（過去記事リンク2本）。
- **数字の落差を並べた直後に自分ツッコミ**（「え？」「😭」など）を置くと、シリアスなテーマの息継ぎになる。
  詳細は [samples/2026-06-25-minimum-wage.md](samples/2026-06-25-minimum-wage.md)。

## 反響の大きい記事の要因（分析）
最反響記事「【私の労働観】地方公務員から主夫になり、再就職した話。」（n8244ec1aab4f）から。

- **タイトルで「人生の落差・振れ幅」を一言で示す**。「地方公務員→主夫→再就職」のように安定を捨てた経歴を提示し、【私の労働観】のようなタグを添える。
  **なぜ効く**：読者は「なぜ？」の空白を埋めたくて読み始める（好奇心のギャップ）。本文冒頭で「必ず“どうして？！”と聞かれる」と自ら煽るのも効く。
- **原点の自己開示は、長く深く書いてよい**。通常の約1,800字の例外（この記事は約8,000字）。
  **なぜ効く**：反響記事は「情報」より「人生の熱量・物語」で伸びる。深い自己開示は共感と保存を生む。
- **希少な経歴 × 普遍的な問い**の掛け合わせ。経歴は珍しく、問いは万人共通（「ルールに従う苦痛」「地位と名誉 vs 心の満足度」）。
  **なぜ効く**：珍しさで惹きつけ、普遍性で自分ごと化させる。
- **損得の両面を正直に書く**。「辞めなければ地位も収入もあった」と損を認めたうえで問い返す。
  **なぜ効く**：きれいごとにしないと信頼が生まれる。[[批判は理解とセット]]と同系統。
- **普遍的な問いで読者に問い返して締める**（「心の満足度はどうだろうか」）。
  **なぜ効く**：自分語りを読者自身の問いに変換すると、共感とコメントが生まれる。
- **時系列の見出しで階段状に読ませる**（経緯→転職→意欲喪失→無職→主夫→再就職）。
  **なぜ効く**：長文でも物語の段差で追える。

## 構成・推敲の型（執筆技法）
2026-06-29「『裏側』は、採用ページに載らない」で固まった型。

1. **本筋から逸れる話は、編集後記に逃がす**。
   その回の記事は1テーマに絞る。関連はするが軸からずれる話（例：制度の記事における残業代）は、本文に混ぜず「## 追記」「編集後記」として末尾に置く。本筋が濁らず、書きたいことも捨てずに済む。
2. **批判は、相手への理解と敬意とセットにする**。
   会社・制度などを否定的に書くときは、断罪で終えない。直前か直後に「相手側の事情も分かる」という一文を置く（例：「働く側を自由にさせすぎても現場は回らない」）。writing-style A の「個人の体験として語る／断罪しない」を具体化したもの。
3. **複数項目は、文に詰めずリスト化する**。
   「Aと、Bと、C」と一文に並べず、改行した箇条書きにする。スマホで読みやすく、リズムも生まれる（例：いい面／暗い面の列挙、契約条件の「1日5時間／週25時間／週5日」）。
4. **心の声・本音は、括弧の独り言にする**。
   地の文で言い切らず、（ ）の中にそっと置く。自虐やツッコミの息継ぎになり、断定を和らげる（例：「（と、わかったふうに書いてみる）」）。writing-style F-4。

### 英訳っぽい日本語を避ける（深掘り）
「英語を直訳したような不自然な日本語」を使わない。具体的には次の癖を疑う。

- **定型の前置きの直訳**を避ける。
  - 「正直に言うと」（To be honest）→「本音を言えば」「内心では」
  - 「勘違いしないでほしい」（Don't get me wrong）→「それでも、〜は本当だ」のように内容で言い換える
  - 他に注意：「言うまでもなく」「〜という意味で」「あえて言うなら」も直訳調になりやすい
- **人称代名詞の入れすぎ**を避ける。「私は」「あなたは」を毎文に置かない。日本語は主語を省ける。
- **「〜することができる」**（canの直訳）を避け、「〜できる」「〜する」に縮める。
- **抽象名詞＋する／の存在**を避ける。「〜という事実」「〜の存在」→具体的な動詞や描写に。
- **接続詞をいちいち明示しない**。「しかし」「したがって」を多用せず、文の並びで論理を見せる（writing-style C と同方向）。
- 見分け方：音読して「翻訳小説っぽい」「ビジネス英語の和訳っぽい」と感じたら直す。話し言葉で言い直すと自然になることが多い。
- 追加パターン（参考：[k16shikanoの文章規範](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d)）：
  - 「〜において」「〜という側面から」は、新情報のない英語的な型。素直な助詞（「〜で」「〜から」）に直す。
  - ダッシュ（──／—）を地の文や見出しの「同格・補足」に使わない。日本語では括弧（）にする（英語的な挿入の癖）。

### LLMっぽい無内容な型を避ける
AIが生成しがちな「中身のない型」を使わない（参考：[k16shikanoの文章規範](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d)）。Claudeに下書きさせたときも、ここを最優先で削る。

- **予告・総括の型**：「重要なのは〜である」「本章では〜」「要するに」「〜に他ならない」。言い換えただけで新情報がないなら消す。
- **空虚な形容**：「不可欠」「核心的」「鍵となる」「多角的」「包括的」「総合的」。何をどう見たかを書いていない強調語は削る。
- **空虚な動詞**：「掘り下げる」「言語化する」「触れる」「言及する」。実際に何を書いたかで示す。
- **接続の連打**：「さらに」「また」を続けない（writing-style C と同方向）。
- **冗長の排除**：同じ主張を言い換えて繰り返さない。場面描写の直後に内容を要約し直さず、意味づけは一文だけ置く。

> 注：この規範は技術文書向けで、「決め台詞の独立段落」「余白語尾（かもしれない）」を抑制せよとも言うが、そこは**つるの文体（writing-style.md）を優先**し、取り込まない。

## 公開時の最終校正でつるがやること（文体・装飾）
2026-06-30「不安は的中した」の公開版で観察。下書きを note 管理画面で仕上げるときの手癖。次の下書きには最初から織り込む。

- **太字は「核心の一文」と「引用の効かせどころ」だけに打つ**。多用しない。例：「**その頑張りが点のままで、線にならない。**」、引用内の「**「現場の協力がほしい」**」。1記事で2〜3箇所まで。
- **絵文字を皮肉・感情の差し込みに少量使う**。建前の皮肉（☺️）、本音（😢）、力の抜けた締め（白目）。地の文のギアチェンジに使い、連発はしない。
- **締め（まとめ）を引用ブロック（>）で独立させる**ことがある。手紙の追伸のように視覚的に切り離す。
- **見出しは、より短く言い切る方向に直す**。「届いたのは、特別警報」→「特別警報がきた」。体言止め・口語で短く。
- **生の独り言を地の文に足す**。「さて、どうする。」「なんか違うし遅い…。うん。」推敲で整えすぎた所に、口語のリアルを戻す。
- **読点の連打（、、、）で口ごもり・余韻**を出す。「（厳しすぎるかな、、、）」。
- **生々しい実数を箇条書きに後から足す**。「メンタルで休職」「2年半で6人退職」など。

### 用語説明・リンクの好み（Claude向けの調整）
- **用語説明に、重い引用解説ボックスを作らない**。語そのものにインラインリンクを貼る軽い形を好む（IT補助金の解説ブロックは、`[IT補助金](url)` の一語リンクに直された）。次回は最初からインラインリンク案で出す。
- **関連過去記事リンクは、記事のトーンで採否が変わる**。生っぽい・感情的な記事では入れないこともある（今回は提案した2本とも公開時に外された）。STEP 2.5では「そもそも入れるか」を先に一言確認し、押し込まない。

## AIドラフト→本人修正で加わるもの（差分の教訓）

### 2026-07-09「3人目が生まれる。嬉しいけど、家計が心配。」の差分

  → writing-style E（数値化）。ドラフト段階で、程度・帰結はできる限り数字と動詞にする。

- **対句で対比を立てる**。「出ていくお金は確実に増える。／入ってくる月収は変わらない（涙）」。増える vs 変わらない を並べ、絵文字で息継ぎ（writing-style A）。

### 2026-07-24「丸投げには、丸投げで返す」の差分
Claudeの下書きを、つるが2回に分けて全面推敲した差分から。全体に「もっと直球・もっと具体・もっと分割」の方向。

- **社長メッセージなど第三者の発言の引用は、`>` ブロック＋核心部分だけ太字にする**。「」インライン引用より視覚的に効く。複数文の引用は、原文の区切りごとに`>`を分けて改行する（1つの`>`に詰め込まない）。
- **実数の開示は、抽象語より思い切って入れる**（「対価も低い」→「時給1,430円で経営まで首を突っ込むのは、さすがに割に合わなすぎる」）。具体と皮肉が同時に効く。writing-style Eの「伏せがちな実数の開示」を、抽象的な形容の代わりに使う判断は本人がする。
- **批判の前に、好意を一段深く先出しする**。段落の頭に「助けてあげたい。頑張って業績回復に貢献したい。」を置いてから「しかし」で構造的な限界に転じる。Claude版は批判が先で好意はあとから弱く添えがち。
- **理解のベクトルは、相手（社長）だけでなく間に立つ人にも向ける**。「きっと社長に急かされて、依頼者も焦ってるんだと思う」のように、直接の不満対象の背後にいる人にも一段共感を挟んでから、それでも「（それにしても雑すぎる）」と本音を残す。
- **1つのh2に2テーマ詰め込まない。標準3h2の目安に縛られず、論旨が変わったら見出しを切る**。今回は最終的に6見出しまで分割された。

- **個人的な固有の比喩（スポーツ観戦など）を締めの最後の一文に置くと、重いテーマでも強い印象を残す**（「WF決勝のアルゼンチンのように、とにかく耐える。」）。Claudeが創作できないlived detailの典型例。
- **ユーモア・色づけの箇所数は、writing-style Fの上限（1記事2〜4箇所）を超えることがある**（本記事は最終的に6箇所前後）。暗いテーマほど、本人は色づけを増やす傾向がある。上限は目安であり、本人の温度感が優先される。
- **たまには締めに、少し分かりにくい固有の比喩をあえて使う実験をしてよい**（今回は「WF決勝のアルゼンチンのように、とにかく耐える」）。狙いは記事に個性を出すこと。ただし伝わらないリスクがあるので、**分かりにくさは`>`ブロックの補足とセットで解消する**（記事最後に試合展開を説明）。本文の余韻は汚さず、注釈自体も「という補足笑」と軽いトーンで締めて重くしない。「本筋から逸れる話は編集後記に逃がす」の具体例＋新しい運用パターン（比喩→本文で余韻→引用ブロックで補足）。

### 2026-07-28「AIで作業は減った。仕事は減っていない。」で分かったこと（工程の教訓）
この記事で、Claudeのドラフトをつるが**全面的に書き直した**。差分そのものは記録できなかったが（`draft.md` を上書きしてしまい、Claude版が消失）、そこから出た教訓のほうが大きい。

- **いきなりドラフトを出すと、書き直しの量が「推敲」ではなく「作り直し」になる**。今回はテーマ・見出し・引用の取捨がまるごと変わった。文レベルのズレではなく、**構成レベルのズレ**だったので、本文を直すコストが高すぎた。
  → **`write-article` に STEP 3「目次（outline.md）」を新設**。テーマ候補 → 質疑応答 → 目次の承認 → 執筆、の順に変更（2026-07-31）。ズレは見出しの段階で潰す。
- **テーマはClaudeが1つに決めず、2〜3案出して選んでもらう**。素材が長く濃いと、Claudeが選んだ軸とつるが書きたい軸がずれる。→ STEP 1に反映。
- **`draft.md` を上書きしない**。つるが全面推敲するときは `draft-tsuru.md` にコピーしてから直す。Claude版を残さないと、この「差分の教訓」シリーズが積み上がらない（記事フォルダは git 管理外のことがあり、gitからも復元できない）。
- **メタファー（将棋・囲碁などの例え話）は、現場の話の"後"に置く**。先に「何のメタファーなのか」＝自分の仕事で何が起きているかを出しておかないと、読者は「急に将棋の話？」で止まる。**現場 → 例え話 → 自分に返す**、の順。
  重複を統合するときに、統合した塊をどこに置くかまで考える。今回は「同じ話が2箇所にある」ことだけ見て統合し、メタファーの前に置いてしまってつるに指摘された（2026-07-31）。
  副次効果として、盤上ゲームの節（将棋・囲碁）が隣り合うと段差が消える。**同じ題材の節は離さない**。
- **下書きに残った執筆メモ（「（確認：〜を出したい）」）は、勝手に削らず必ず意図を聞く**。今回Claudeは「天才数学者の例」を将棋と重複と判断して削ったが、つるの意図は別だった。
  - 将棋＝**判別力の差**（プロには分かる、初心者には分からない）
  - 数学＝**シンプルに見えることと、実際にできることは別**（未解決問題ほど問い自体は簡単）
  一見似た例え話でも、担っている論点が違うことがある。**似ているから削る、をやらない**。メモは本人の思考の痕跡なので、消す前に聞く。
- **締めの「前向きな一手」は、本人がすでにやっている実務から出てくる。Claudeが決意を創作しない**。
  今回Claudeは仮で「AIが出した答えを、そのまま人に渡さない」と書いたが、つるの実際は違った——「レビューは半ば諦めた。代わりに、入出力の見当と、壊れる範囲の限定だけは手放していない」。諦めを含んだぶん、こちらのほうが圧倒的に本物だった。
  → STEP 2の質疑応答に「すでにやっている対処や工夫はあるか」を追加。**「今、実際にどうしていますか」と聞けば出てくる**。
- **つるが参考記事のURLを渡してきたら、要約で済ませず「その記事のどこに同意したか」を聞く**。今回は深津貴之氏の記事から「人間が握るべきは中身の理解ではなく、入出力・境界・停止条件・責任分界」という論点を拾い、それが記事の締めの核になった。渡された参考記事は、論の裏付けであると同時に**本人の実践を引き出す呼び水**になる。

> 素材（memo.md）と、つるが書き直した本文を並べて読むかぎり、方向としては以下だった。※Claude版が無いため確証ではなく推定。
> - **重い外部研究の引用は1本まで**。素材にあった研究・論文のうち2本が落ち、残ったのは1本だけ。学術の厚みより自分の体験が主。
> - **自分の過去記事リンクが3本足された**。「ググらなくなった」「Cursorを契約した頃」「AIでスキルアップに違和感」。自分史の連続として読ませる方向。
> - **時系列の自己対比（かつての私 vs 今の私）が足された**。他人の研究より、自分の変化のほうを軸に置く。
> - **見出しが「〜する理由」「〜が現実になって現れた」のように長く説明的**になった。直球の言い切り志向は共通。
