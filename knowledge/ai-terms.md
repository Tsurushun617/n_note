## 1. AIは学習しない。毎回、忘れる（今回の最重要）

Claude Code が自分のパソコンの中のファイルを読んでも、**AIはそれを覚えない。**

読んだ内容は、その会話の**コンテキスト（文脈）**に一時的に載るだけ。
会話を閉じれば消える。次に立ち上げたときには、何も知らない状態から始まる。
モデルそのもの（LLMの中身）は、こちらの使い方では書き換わらない。

- ×「LLMとして、学習データとして大量に取り込んでくれる」
- ○「読み込んで、その会話のあいだだけ覚えている」

**だから毎回、同じマニュアルを渡し直すことになる。**
`CLAUDE.md`（プロジェクトの決まりごとを書いたファイル）を毎回自動で読ませているのは、そのため。
教育ではなく、**毎朝おなじ引き継ぎ書を机に置く**のに近い。

> 牛尾剛さんも同じことを書いている。
> > エージェントは「忘れる」からです
> （[AIエージェントの最良のマネージャになる方法](https://note.com/simplearchitect/n/n99d6744b877d)・2026-02-28）

## 2. LLM（大規模言語モデル）

Large Language Model。「ライブリングモデル」は音声入力の誤変換。

大量の文章で訓練された、次に来る言葉を予測する仕組み。
訓練が終わった時点で中身は固定される。使っているあいだに賢くなることはない（→ 1）。

Claude、ChatGPT、Gemini は、いずれもこのLLMを積んだ製品。

---

## 3. 「スコープ」の正体は、3つ別のもの

「自分が限定した範囲」と言っているものは、実際には3種類ある。分けて書いたほうが正確。

1. **作業ディレクトリ** … どのフォルダを起点に動くか。ここから外は基本的に触らない
2. **権限（permissions）** … どのコマンドの実行を許すか。毎回確認を出すか、許可しておくか
3. **読ませるファイルの範囲** … その作業に必要なファイルだけを渡す。関係ないものは渡さない

つるが実際にやっているのは、この3つを場面ごとに締めたり緩めたりすること。
「スコープ」と一語で言うと、この3つが混ざる。

> 補足：Claude Code の設定にも「スコープ」という語はあるが、そちらは
> **設定の適用範囲**（自分だけ／プロジェクト全体／この端末だけ）を指す別物。同じ語で別の意味。

## 4. チャットとエージェントの差は、「賢さ」ではなく「行動できるか」

ここがメモで一番ぼやけている箇所。

- **ブラウザのチャット欄**（ChatGPT・Gemini・Claudeのアプリ）
  → 質問を受けて、**テキストを返して終わり**。実際に何かをするのは、返事を読んだ人間
- **エージェント**（Claude Code など）
  → ファイルを読む・書く・コマンドを実行する、といった**行為ができる**。
  そして**その結果を見て、次に何をするかを自分で決める**。この繰り返し（ループ）が「自律的」の中身

「自律的」というのは、賢いという意味ではない。
**手を動かして、結果を確認して、また手を動かせる**という意味。
だから「質問する」ではなく「働かせる」になる。

> 注意：**ChatGPT や Gemini にもエージェント型の製品はある**（コード用のCLIなど）。
> 「ChatGPT＝チャット、Claude＝エージェント」と製品名で切ると事実として間違う。
> 比べるなら「ブラウザのチャット欄」と「ターミナルのエージェント」で比べる。

## 5. AIは毎回インターネットを検索しているわけではない

メモの「インターネット上のデータを検索して、それをつなぎ合わせて回答」は、半分だけ正しい。

基本は、**モデルの中にすでにある知識**で答えている。
検索するのは、新しい情報が要るときや、AIが「これは調べたほうがいい」と判断したときだけ。

Claude Code の場合はそこに、**手元のパソコンのファイルを読む**という手段が加わる。
「ネット＋ローカル」という並べ方自体は合っている。

## 6. コンテキストウィンドウ／トークン／モデルの使い分け

**トークン**：AIが文章を数えるときの単位。ざっくり「文字のかたまり」。
入力（読ませた量）と出力（書かせた量）の合計で料金が決まる。

**コンテキストウィンドウ**：AIが一度に見ていられる量の上限。
記憶ではなく**机の広さ**に近い。広さはモデルとプランで変わるので、**数字を書くときは必ず確認する**。

読ませすぎると、3つとも悪くなる。

1. 上限に当たって、古い部分が押し出される
2. 大事な指示が大量の情報に埋もれて、精度が落ちる
3. 料金が上がる

つるの「必要のないコンテキストを読み込ませない」は、この3つ全部に効いている。

**モデルの使い分け**（2026-08時点の Claude）

| モデル | 向いている仕事 |
|---|---|
| Opus | 方針の判断・設計・曖昧な指示の読み解き |
| Sonnet | バランス型。ふつうの実装・調査 |
| Haiku | 軽い機械作業。速くて安い |

メモの「性能の低いモデルは、精度が低く、読むコンテキストの量も低くなる」は、
**2つの別の軸が混ざっている**。

- **推論の質**（難しい判断ができるか）… モデルの性能差
- **一度に読める量**（コンテキストウィンドウ）… モデルごとの仕様

安いモデルに難しい判断を振ると精度が落ちるのは事実。
ただし理由は「読める量が少ないから」ではなく「判断の質が違うから」。

**料金の話**も正確には逆向き。
高性能なモデルを使うと**トークンの消費量が増える**のではなく、**同じ量でも単価が高い**。

## 7. サブエージェント＝別の机で働く部下

親の会話とは**別のコンテキスト**で動く。
調べ物を丸ごと任せて、**結果だけを返してもらう**。親の会話は汚れない。

メモの「Aという課題をAとA'に分解して、AはBさんに、A'はCさんにお願いする」は、
まさにこれの実装そのもの。

つる自身の `CLAUDE.md` にも、すでにこう書いてある。

> 調査・照合・機械的チェック → サブエージェント（Sonnet）に任せる
> 方針判断・設計・曖昧な指示の解読 → メイン（Opus）で行う

**これは人選そのもの。**

---

## 8. ターミナル5枚＝5セッション並行

タブを5つ開いているのは、**5つの独立した会話を同時に走らせている**状態。

それぞれが自分のコンテキストを持っていて、**互いの記憶を共有しない**。
1枚目で決めたことを、2枚目は知らない。

後輩を5人育てるのとは、ここが決定的に違う。
人間のチームは、隣の席の会話が耳に入る。エージェントには入らない。

## 9. MCP・スキル・CLAUDE.md（「マニュアルを渡す」側の道具）

| 用語 | 何か |
|---|---|
| **CLAUDE.md** | プロジェクトの決まりごとを書いたファイル。毎回自動で読ませる引き継ぎ書 |
| **スキル** | 特定の作業の手順書。必要になったときだけ読み込まれる |
| **権限設定** | 何を許可し、何を毎回確認させるか |
| **MCP** | AIに外部サービス（Figma・Gmail・Notion など）を触らせるための共通の接続規格 |

すべて「AIに何をどこまでやらせるか」を人間側が決めるための道具。
どれも**学習させる仕組みではない**（→ 1）。毎回渡すための仕組み。

## 記事で使うときの注意

- **数字は書くたびに確認する。** 契約プランの月額、コンテキストウィンドウの大きさ、モデル名は変わる
- **製品名で断定しない。** 「ChatGPTは〜できない」は半年で嘘になる。**自分がどう使っていたか**で書く
- 用語の説明は、重い解説ボックスではなく**語そのものへのインラインリンク**を優先する
  （[note-learnings.md](note-learnings.md)「用語説明・リンクの好み」）
- 専門語を出したら、その場で口語に落とす（[writing-style.md](../.claude/rules/writing-style.md) 0項-1）
